# Live Watch (Cortex-Debug) setup — problem & solution log

Goal: watch `blink_counter` (a `volatile uint32_t` global in `src/main.c`) update in real time while the STM32 is running, without hitting a breakpoint — equivalent to STM32CubeIDE's "Live Expressions".

This took several iterations because the failure surfaced in layers — each fix revealed the next blocker. Documented here so it isn't re-debugged from scratch next time.

## Problem 1 — `liveWatch` key in `launch.json` kept disappearing

**Symptom:** Added `"liveWatch": { "enabled": true, "samplesPerSecond": 4 }` to the `platformio-debug` configs in `.vscode/launch.json`. It worked once, then vanished after the file was touched again.

**Root cause:** `.vscode/launch.json` is regenerated by PlatformIO from a template (`platformio/project/integration/tpls/vscode/.vscode/launch.json.tpl` in the PlatformIO core package). That template hardcodes a fixed field set (`type`, `request`, `name`, `executable`, `projectEnvName`, `toolchainBinDir`, `internalConsoleOptions`, `svdPath`, `preLaunchTask`, `loadMode`) for any config whose `type == "platformio-debug"` and whose `name` matches one of its three known names ("PIO Debug", "PIO Debug (skip Pre-Debug)", "PIO Debug (without uploading)"). Any extra key added to those specific entries — `liveWatch` included — gets silently discarded on the next regeneration.

**Deeper issue found while investigating:** even when present, that key did nothing. PlatformIO's own bundled debug adapter (`type: "platformio-debug"`) has **zero** references to `liveWatch` anywhere in its Python core or its VS Code extension bundle — it doesn't implement Live Watch at all. The "CORTEX LIVE WATCH" panel is a feature specific to the separate `marus25.cortex-debug` marketplace extension, which turned out not to be installed in this environment.

**Fix:**
1. Installed the `marus25.cortex-debug` extension (`code --install-extension marus25.cortex-debug`).
2. Added a **new, independently-typed** config to `launch.json`: `"type": "cortex-debug"`, name `"Cortex Debug (Live Watch)"`. Since PlatformIO's regenerator only ever touches entries matching `type == "platformio-debug"` + one of its three names, this entry is invisible to it and survives regeneration permanently.
3. Removed the now-pointless `liveWatch` keys from the three `platformio-debug` entries.

## Problem 2 — new debug config produced no output at all

**Symptom:** Hit F5 on "Cortex Debug (Live Watch)" — Run & Debug icon flashed a `1` badge then immediately stopped. Nothing appeared in the "Cortex-Debug" Output channel.

**Root cause:** The `cortex-debug` extension had just been installed via CLI while VS Code was already running. Extensions installed this way need a window reload before their debug-adapter registration (contribution points) actually takes effect — until then, selecting the config fails before it ever reaches OpenOCD/GDB.

**Fix:** `Ctrl+Shift+P` → **Developer: Reload Window**.

## Problem 3 — `GDB could not start as expected. Bad installation or version mismatch`

**Symptom:** After the reload, the session progressed further but VS Code popped an error dialog: *"GDB could not start as expected... Must be >= 9"*.

**Root cause:** Two ARM toolchain packages exist in `~/.platformio/packages/`:
- `toolchain-gccarmnoneeabi@1.70201.0` (the one used for compiling, and what `launch.json`'s `gdbPath`/`armToolchainPath` pointed at) → GDB **8.0.50** (2017) — too old, Live Watch needs GDB ≥ 9 for its async/background execution MI features.
- `toolchain-gccarmnoneeabi` (unversioned, newer) → GDB **13.2.90** — works.

**Fix:** Repointed `armToolchainPath` and `gdbPath` in the `"Cortex Debug (Live Watch)"` config to the unversioned `toolchain-gccarmnoneeabi/bin` directory. This only affects the debug session, not the build (which still uses the versioned toolchain PlatformIO selected).

## Problem 4 — variable showed with no type / Live Watch couldn't read it properly

**Symptom:** Command-line GDB sanity check (`print blink_counter`) returned *"'blink_counter' has unknown type; cast it to its declared type"*.

**Root cause:** `platformio.ini` had no `build_type` set, so PlatformIO built in plain release mode with no `-g` — the ELF had only a `.debug_frame` section (unwind info), no `.debug_info`/`.debug_line`/`.debug_str`. GDB could see the symbol's address (from the symbol table) but had no DWARF type information to interpret it.

**Fix:** Added `build_type = debug` to `platformio.ini` (`[env:bluepill_f103c8]`). Rebuilt — ELF gained full DWARF sections; `whatis blink_counter` now correctly reports `volatile uint32_t`.

## Problem 5 — "not available" in the Watch panel even though everything above was fixed

**Symptom:** After hitting Continue past the `main` entry breakpoint, the **Watch** panel showed `blink_counter = not available`.

**Root cause:** Not a bug — user confusion between two different panels. The plain **Watch** panel can only evaluate expressions while GDB is halted at a stopped frame; while the target is running freely (which is the whole point of Live Watch), standard Watch always shows "not available". The actual polling panel is the separate **Cortex Live Watch** section (collapsed, near the bottom of the Run & Debug sidebar, below Breakpoints) — that's the one driven by the `liveWatch` config block and the 4-samples/sec OpenOCD polling.

**Fix:** Expand **Cortex Live Watch**, click its `+`, add `blink_counter` there instead. Confirmed working — value updates live while the CPU runs.

## Final working configuration

`.vscode/launch.json` — `"Cortex Debug (Live Watch)"` entry (type `cortex-debug`):
- `servertype: "openocd"`, `serverpath` → PlatformIO's bundled `tool-openocd/bin/openocd.exe`
- `armToolchainPath` / `gdbPath` → the **unversioned** `toolchain-gccarmnoneeabi` package (GDB ≥ 9)
- `configFiles`: `interface/stlink.cfg`, `target/stm32f1x.cfg`
- `openOCDPreConfigLaunchCommands: ["set CPUTAPID 0"]` — must run *before* `configFiles` are sourced (matches how PlatformIO's own upload path orders it, since `target/stm32f1x.cfg` reads `CPUTAPID` at source time for this clone board)
- `liveWatch: { enabled: true, samplesPerSecond: 4 }`

`platformio.ini` — added `build_type = debug` so builds retain full DWARF debug info.

`src/main.c` — `volatile uint32_t blink_counter;` global, incremented once per LED toggle.
